## Figma: источник и ручное сравнение

Через подключённый API get_design_context/create_session получен отказ в доступе. В браузере файл доступен для просмотра: выбран тёмный Main_left menu, node 1:43, 1920×1080, выполнен штатный Export PNG 1x. Этот PNG подключён к Bridge через --reference, а не через фиктивные metadata Downloader. SHA-256 и источник сохранены рядом с эталоном. Нативные снимки браузера имеют размер поверхности приложения; точные viewport-снимки требуемых размеров сняты Playwright.

Изображения эталона и actual просмотрены вручную. Совпадают общая тёмная тема, набор основных блоков, изображения подборок, поля поиска, плеер и форма кнопок. Ранее обнаруженные отличия Montserrat и отступов исправлены. Используется локальный StratosSkyeng Web Regular (внутреннее начертание Regular, weight 400), проверенный по данным файла и метрикам текста в Figma. При 1920 px основной контент теперь начинается на x=294, первая строка на y=388, подборки на x=1580/y=428. Поиск имеет ширину 1293 px; колонки исполнителя и альбома начинаются на x=775 и x=1096. Браузерный тест проверяет загрузку шрифта, ширину Guilt около 33 px при 16 px и заголовка около 172 px, а также позиции ключевых блоков с допуском менее 1 px. Треки взяты из требуемого data.ts, а не из декоративных примеров Figma. Эталон Main_left menu показывает открытое меню; закрытая начальная видимость проекта сохранена по пользовательской реализации. Начальное состояние меню и данные сохранены по требованиям задания. Попиксельная идентичность всех состояний не заявляется.

Технический PASS Bridge не является автоматическим визуальным PASS: pixel diff инструментом не выполняется. Дизайн Figma и API-права не изменены.

## Пять решений для самостоятельного объяснения

1. Почему FilterName | null исключает два одновременно открытых фильтра и зачем setState принимает функцию с предыдущим состоянием.
2. Как map/flatMap и Set получают уникальные списки из Track[] без any и почему genre требует flatMap.
3. Почему стабильный key track._id/уникальное значение лучше индекса массива и как props Track проверяются TypeScript.
4. Как button, aria-expanded, aria-controls, фокус и клавиатура обеспечивают доступное управление; зачем use client нужен только интерактивным компонентам.
5. Чем проверка tsc/lint/build отличается от браузерных тестов и почему технический PASS Bridge не доказывает визуального совпадения.
