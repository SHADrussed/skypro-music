# Разбор для самостоятельной практики

## Redux Store, actions и reducers

Store хранит общее состояние приложения. Action описывает событие или намерение изменить состояние. Reducer получает текущее состояние и action и возвращает новое состояние. В Redux Toolkit `createSlice` создаёт actions и reducers вместе; Immer позволяет писать обновления в привычном изменяемом стиле, сохраняя неизменяемость снаружи.

Упражнение: добавьте в состояние плеера признак повтора и action для его переключения. Типичная ошибка — менять объект состояния вне reducer.

## Аудиоплеер и useRef

`useRef` хранит ссылку на DOM-элемент `<audio>` между рендерами. Через неё можно вызвать `play()`, `pause()` и прочитать текущую позицию без поиска элемента в DOM. Значение ref не вызывает новый рендер.

Упражнение: добавьте кнопку перехода к началу текущего трека. Типичная ошибка — ожидать, что изменение `ref.current` само обновит интерфейс.

## async/await и ошибки

`async`-функция всегда возвращает Promise. `await` приостанавливает её выполнение до завершения Promise. `try/catch` ловит ошибки сети и явно выброшенные ошибки. Fetch не считает HTTP 4xx/5xx исключением: проверяйте `response.ok` и формируйте понятное сообщение.

Упражнение: обработайте отдельно неверный пароль и недоступность сервера. Типичная ошибка — разбирать JSON до проверки статуса и терять полезное сообщение API.

## Серверные запросы в Next.js

Server Components могут загружать данные при рендере страницы. Клиентские компоненты подходят для интерактивного состояния и событий пользователя. `loading.tsx` показывает состояние загрузки сегмента, `error.tsx` — границу восстановления после ошибки. Кеширование задавайте осознанно: каталогу с меняющимися данными может требоваться свежий ответ.

Упражнение: добавьте страницу подборки с загрузкой, ошибкой и пустым состоянием. Типичная ошибка — объявить компонент клиентским без необходимости и передавать ему слишком много данных.

## Access и Refresh-токены

Access-токен отправляется с защищёнными запросами и обычно живёт недолго. Refresh-токен обменивается на новый access-токен. Токены нельзя писать в логи. Хранение в localStorage доступно JavaScript, поэтому XSS может их прочитать; следуйте контракту учебного API и очищайте данные при выходе.

Упражнение: опишите сценарий истечения обоих токенов. Типичная ошибка — считать, что refresh-токен можно отправлять вместо access.

## withReAuth

Обёртка выполняет запрос с access-токеном. При первом 401 она запрашивает новый access с refresh-токеном, сохраняет его и повторяет исходный запрос ровно один раз. Если обновление не удалось, сессия завершается. Одновременные 401 желательно объединять в один refresh Promise.

Упражнение: добавьте защиту от повторного refresh при 401 на повторном запросе. Типичная ошибка — бесконечно повторять запрос.

## Лайки и серверная синхронизация

Сервер является источником истины для избранного. Интерфейс может обновиться оптимистично, но при ошибке следует откатить изменение. Для отображения лайка сравнивайте список избранных ID с ID текущего трека. После выхода очищайте приватное состояние.

Упражнение: спроектируйте обработку двух быстрых нажатий на лайк. Типичная ошибка — оставить UI в изменённом состоянии после неудачного запроса.

## useMemo, useCallback и React.memo

`useMemo` сохраняет результат дорогого вычисления между рендерами. `useCallback` сохраняет ссылку на функцию, когда стабильность ссылки важна для дочернего компонента или зависимости эффекта. `React.memo` пропускает рендер компонента, если его props не изменились. Используйте их после выявления лишней работы: мемоизация тоже имеет стоимость.

Упражнение: измерьте список треков до и после мемоизации элемента списка. Типичная ошибка — оборачивать каждую функцию в `useCallback`, не имея проблемы со стабильностью props.
