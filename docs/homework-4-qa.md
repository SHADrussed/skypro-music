## Реализация и поведение

Используется существующий `playerSlice`, Provider и единственный audio/ref в PlayerBar. Отдельного AudioPlayer в исходной архитектуре нет; новый независимый плеер не создавался. `currentTrack` остаётся в Redux; HTMLAudioElement, Promise и DOM-объекты в store не попадают.

- Redux хранит текущий плейлист из существующих моковых данных, текущий трек, фактическое `isPlaying`, Shuffle/Loop, громкость 0–1, историю и оставшиеся треки Shuffle.
- Next/Previous переключают источник и запускают выбранный трек. В обычном режиме первый/последний треки ограничивают навигацию; пустой выбор также блокирует кнопки.
- Нативный `ended` включает следующий трек. На последнем треке обычного плейлиста воспроизведение останавливается без перехода к началу.
- Shuffle выбирает случайный трек из ещё не воспроизведённых в текущем цикле. На границе циклов исключается текущий трек. Previous возвращается по фактической истории; Next после Previous сначала идёт вперёд по истории. Ручной выбор трека и переключение Shuffle начинают новую историю от текущего трека. Отключение Shuffle возвращает исходный порядок плейлиста.
- Случайное число генерируется при создании action, reducer остаётся детерминированным.
- Loop задаёт `HTMLAudioElement.loop`; нативный повтор имеет приоритет над Shuffle и обычным `ended`. Next/Previous вручную по-прежнему переключают трек.
- Время и длительность считываются из audio через metadata/duration/time/seek-события. Локальный снимок прогресса не выбирает трек и сбрасывается при смене источника. Seek задаёт `currentTime`; на паузе перемотка сохраняет паузу.
- Volume меняет `audio.volume`; `volumechange` синхронизирует Redux. Режимы и громкость не перезапускают источник и сохраняются при переходе между треками.
- Сохранены обработка `play()` rejection, ошибок источника, повторная загрузка после ошибки, отмена ожидающего запуска, защита от устаревшего Promise, остановка при уходе со страницы и фактический индикатор воспроизведения.

## Проверки

- `npx tsc --noEmit` — PASS.
- `npm run lint` — PASS, без предупреждений ESLint.
- `npm run build` — PASS.
- Финальный полный прогон: `$env:QA_REAL_AUDIO='1'; npm run qa` — **64 PASS, 0 FAIL, 2 SKIP**, без flaky-тестов, 4.7 минуты; [машинный отчёт и диагностика](advanced-player-qa/playwright.json). Два SKIP — существующая проверка desktop-якорей Figma на mobile/tablet; на desktop она прошла.
- `npm run qa:visual` — PASS; [Figma QA Bridge](advanced-player-qa/figma-bridge.json), [снимок 1920 px](advanced-player-qa/figma-actual.png). Эталон и SHA-256 не изменены. Bridge не выполняет pixel diff.

Новые проверки выполняются на 375×700, 768×1024 и 1440×900. Проверяются границы и Next/Previous, естественный ended, полный цикл Shuffle без повторов, переход между циклами, история назад/вперёд, отключение Shuffle, Loop при одновременно включённом Shuffle и переход после отключения Loop, seek 0/середина/конец, громкость 0/0.5/1, сохранение настроек, единственный audio и геометрия. Все прежние проверки загрузки/404/retry/play rejection/отмены/навигации сохранены. Старый тест окончания трека теперь проверяет последний трек, поскольку на остальных требуется автоматический переход.

Контролируемый PCM WAV действительно декодируется Chromium; HTTP Range поддерживает настоящую перемотку. Успех воспроизведения требует готового декодера и роста `currentTime`, а не только изменения иконки. Только тест отклонённого `play()` намеренно подменяет первый вызов.

Отдельные тесты без перехвата ответов воспроизводят все 10 внешних MP3 и проверяют новые элементы управления на реальном MP3: seek в начало/середину/к концу, громкость 0/50/100%, нативный переход Loop через конец, приоритет Loop над Shuffle, автопереход после отключения режимов, Next/Previous во время воспроизведения. Длительность берётся из декодера, а не из мокового `duration_in_seconds`.

## Промежуточная диагностика

Первый отдельный прогон пяти новых desktop-сценариев прошёл. Первый полный прогон: 61 PASS, 3 FAIL, 2 SKIP. Тест реального MP3 передал в range значение с пятью дробными знаками, не соответствовавшее `step=0.01`; Playwright отклонил ввод как malformed value. Дополнительный запуск обнаружил, что строка `0.00` тоже отклоняется: браузер нормализует её в `0`. Тест теперь вводит округлённое до сотых число в канонической строковой форме. Проверка аудио не ослаблялась; отдельный повторный тест реального MP3 прошёл. Результаты окончательного прогона сохраняются отдельно.
